# iPad Display — старый iPad как второй монитор для macOS / Windows

Работает с любым iPad, на котором есть Safari с WebSocket — включая iPad mini 1 (A1432),
iPad 2/3 на iOS 9.3.5, которые не поддерживают Sidecar, Duet и Luna.

```
┌──────────── компьютер (Electron) ────────────┐        ┌──── iPad ────┐
│ захват экрана → JPEG → change-detect →       │ Wi-Fi  │ Safari       │
│   WebSocket-сервер :7800  ───────────────────┼───────►│ index.html   │
│   usbmux.js → usbmuxd (без iproxy) ──────────┼─ USB ─►│ IPadDisplay  │
└──────────────────────────────────────────────┘        └──────────────┘
```

Каждый кадр — целый JPEG. Клиент подтверждает получение (ack), следующий кадр уходит
только после ack, поэтому медленный iPad просто получает меньше кадров, но всегда самый
свежий, без накопления задержки. Неизменившиеся кадры не отправляются вовсе.

## Что делает по умолчанию

При запуске хост сам: выбирает виртуальный монитор (второй экран 4:3), начинает захват,
включает передачу звука (Windows) и приём касаний, слушает UDP-маячки приложения iPad и
подключается к нему по Wi-Fi; если iPad на кабеле, а Wi-Fi нет — через usbmuxd. Настройки
запоминаются в `%APPDATA%\ipad-display\settings.json` (macOS: `~/Library/Application Support/ipad-display/`).

Виртуальный монитор на Windows ставится кнопкой «Установить виртуальный монитор 1024×768»
в панели (драйвер VirtualDrivers/Virtual-Display-Driver, MIT, лежит в `driver/windows/`,
нужен запрос администратора). Его положение относительно основного экрана меняется в
Параметры → Система → Дисплей.

**Звук:** системный звук Windows (loopback) идёт на iPad как PCM 22050 Гц моно. В нативном
приложении играет сразу, в Safari — после первого тапа по экрану (ограничение iOS).
На macOS у Chromium нет loopback-захвата, звук там не передаётся.

**Видео на приложение iPad:** H.264 с аппаратным декодером (AVSampleBufferDisplayLayer), 60 fps.
Кодер выбирается автоматически: на Windows с установленным ffmpeg (`winget install Gyan.FFmpeg`) —
захват `ddagrab` прямо в видеопамяти и аппаратный кодер Media Foundation (NVIDIA/Intel/AMD),
иначе программный H.264 через WebCodecs, иначе JPEG. Панель показывает сквозную задержку
«сеть+декодер» по меткам, которые iPad возвращает на каждый кадр (по USB около 5 мс, по Wi-Fi 7–9).
При воткнутом кабеле хост сам переключается на USB, без кабеля работает по Wi-Fi.

**Отдельное аудиоустройство «как HDMI»:** поставьте VB-CABLE (vb-audio.com, бесплатный). В Windows
появится устройство вывода «CABLE Input» (переименуйте в «iPad Display» в Параметры → Звук), хост
автоматически берёт звук с «CABLE Output» вместо всего системного звука. Направляйте на него
конкретные приложения или систему целиком.

**Касания и жесты:** один палец — мышь (тап = клик, движение = перетаскивание), два пальца —
прокрутка (колесо, горизонтальное тоже), щипок — Ctrl+колесо (масштаб), долгое нажатие —
правая кнопка. Всё это на том мониторе, который передаётся. На macOS нужен python3 с pyobjc (Quartz).

## Быстрый старт (Wi-Fi, ничего ставить на iPad не нужно)

```bash
npm install
npm start
```

1. В окне «iPad Display» выберите экран, который отправлять (для второго монитора —
   виртуальный дисплей, см. ниже). Нажмите **Старт**.
2. На iPad отсканируйте QR-код или откройте в Safari адрес вида `http://192.168.x.x:7800/`.
   Компьютер и iPad должны быть в одной сети.
3. На iPad: Поделиться → **На экран «Домой»**, запускайте с иконки — тогда страница
   открывается на весь экран без адресной строки. Автоблокировку iPad: Настройки → Основные →
   Автоблокировка → **Никогда**.

Настройки качества: размер 1024×768 для iPad mini 1 / iPad 2 (это их родное разрешение),
FPS 10–20, JPEG 50–70. Тап по экрану iPad показывает реальный FPS и трафик.

## Режим «второй монитор», а не зеркало

Программа передаёт картинку выбранного экрана. Чтобы iPad был *дополнительным* экраном,
на компьютере нужен виртуальный дисплей, который система считает настоящим монитором:

- **Windows 10/11** — бесплатный open-source драйвер
  [Virtual Display Driver](https://github.com/VirtualDrivers/Virtual-Display-Driver)
  (IddCx, установка через Диспетчер устройств / прилагаемый установщик). После установки
  в Параметры → Система → Дисплей появится ещё один монитор: поставьте ему 1024×768 и
  «Расширить эти экраны». Альтернатива — `usbmmidd_v2` от Amyuni.
- **macOS** — [DeskPad](https://github.com/Stengo/DeskPad) (open source, бесплатно) или
  BetterDisplay: создают виртуальный дисплей, задайте 1024×768.

Затем в панели выберите этот виртуальный экран. Окна, перетащенные на него, появятся на iPad.

macOS при первом запуске спросит разрешение «Запись экрана» для Electron — дайте его в
Системных настройках → Конфиденциальность.

## Кабель USB

iOS разрешает только соединения *компьютер → iPad* через usbmuxd, а браузер не может
слушать порт, поэтому для кабеля нужно нативное приложение на iPad (`ios/`). Хост подключается
к usbmuxd сам (`usbmux.js`), отдельный `iproxy` не нужен.

**Проверенный путь без Mac (джейлбрейк):** iPad mini 1 на iOS 9.3.5 с EverPwnage + OpenSSH.
Приложение собирается в GitHub Actions (`.github/workflows/ios-build.yml`: clang + ld64 из
Linux-тулчейна theos, iPhoneOS9.3.sdk), затем `node tools/push-app.js out/IPadDisplay.app`
заливает его по SSH через USB в `/Applications`, подписывает `ldid` на устройстве и запускает
через `sblaunch` (iPad должен быть разблокирован). Проверено 2026-09-10: картинка идёт по кабелю.

Полезные инструменты: `tools/ssh.js "<cmd>"` (SSH через usbmuxd), `tools/list-apps.js`,
`tools/device-info.js`, `tools/usb-forward.js <local> <device>`.

На компьютере должен работать usbmuxd:

- **macOS** — есть в системе.
- **Windows** — приложение «Apple Devices» из Microsoft Store (`winget install 9NP83LWLPZ9K --source msstore`).
  Оно должно быть запущено хотя бы раз после подключения iPad: его фоновый процесс
  AppleMobileDeviceProcess и есть usbmuxd (127.0.0.1:27015). Проверено на Windows 11.
  Установка iTunes через winget сама по себе usbmuxd не даёт (компонент Mobile Device Support
  не ставится).

Проверка USB-слоя без iPad-приложения:

```bash
node tools/usbmux-list.js
```

Ожидаемый вывод: серийный номер iPad и «tunnel … failed: устройство отклонило
соединение» — это значит, что туннель работает, а на iPad просто не запущено приложение.
Затем в панели, блок «3b»: режим «USB (usbmuxd)» → **Подключить** → **Старт**.
Тот же блок в режиме TCP работает по Wi-Fi к приложению, если ввести IP iPad.

## Bluetooth

Не реализован намеренно. Сторонним приложениям на iOS доступен только BLE
(десятки КБ/с), а для картинки 1024×768 нужно 1–2 МБ/с. Классический Bluetooth
(iAP2) требует сертификации MFi. Технически это не решается софтом.

## Структура

| Файл | Назначение |
|---|---|
| `main.js` | Electron main: HTTP + WebSocket-сервер (7800), push-клиент к приложению (USB/TCP), рассылка кадров с ack |
| `usbmux.js` | клиент usbmuxd: список устройств и туннель к порту iPad без iproxy |
| `panel.html` | окно хоста: выбор экрана, захват через `getDisplayMedia`, JPEG, детектор изменений, QR |
| `preload.js` | мост renderer ↔ main |
| `client/index.html` | веб-клиент для iPad, ES5, совместим с Safari iOS 9 |
| `ios/` | нативное приложение (Objective-C, iOS 9) для USB |
| `tools/test-client.js` | эмулятор iPad по WebSocket: `node tools/test-client.js ws://127.0.0.1:7800/ 10` |
| `tools/test-tcp-device.js` | эмулятор iOS-приложения по TCP: `node tools/test-tcp-device.js 7801 5` |
| `tools/usbmux-list.js` | проверка usbmuxd и туннеля к iPad по кабелю |
| `tools/ssh.js`, `tools/push-app.js`, `tools/list-apps.js`, `tools/device-info.js` | SSH, установка и диагностика iPad через usbmuxd (или `IPAD_SSH_HOST=<ip>` по Wi-Fi) |
| `driver/windows/` | Virtual Display Driver + `install-vdd.ps1`, ставится кнопкой из панели |
| `ios/tools/sblaunch.c` | запуск приложения по bundle id на джейлбрейкнутом iPad |

Переменные окружения: `IPAD_DISPLAY_PORT` (порт HTTP, по умолчанию 7800),
`IPAD_DISPLAY_AUTOSTART=1` (нажать «Старт» при запуске), `IPAD_DISPLAY_TCP=host:port` или `IPAD_DISPLAY_TCP=usb`
(сразу подключаться к приложению).

## Кодеки

- **H.264** (по умолчанию для нативного приложения): хост кодирует через WebCodecs
  (в Electron на Windows работает программный OpenH264, аппаратные NVENC/MediaFoundation
  через WebCodecs не запускаются), iPad декодирует аппаратно через AVSampleBufferDisplayLayer.
  До 60 fps при 1024×768, 2–8 Мбит/с в зависимости от движения, задержка около 100 мс.
  Протокол: 'H' avcC (SPS/PPS), 'V' AVCC-кадры; iPad шлёт 'K', если потерял синхронизацию,
  хост тогда отправляет ключевой кадр; при переполнении сокета дельта-кадры отбрасываются
  до следующего ключевого.
- **JPEG**: для Safari (в iOS 9 нет MSE) и как запасной режим. Покадровые ack, 10–15 fps на A5.

## Ограничения и что можно улучшить

- JPEG-режим: на iPad mini 1 по Wi-Fi реально 8–15 fps при 1024×768.
- Тач с iPad на компьютер не передаётся (это монитор, не тачскрин). Канал ack уже
  двунаправленный, добавить события касаний в `client/index.html` и инъекцию мыши
  в `main.js` несложно.
- Звук без сжатия (~350 кбит/с), задержка 0.2–0.5 с. HDCP-защищённый контент не захватывается.
